# Дипломный проект: реальный кейс компании «Ростелеком Информационные Технологии»

*Проект подготовлен в рамках дипломного проекта по тестированию.*

Проект содержит набор автоматизированных тестов для проверки ключевой функциональности платформы компании **Ростелеком Информационные Технологии**.

Тесты реализованы на языке **Python** с использованием библиотеки **Selenium** и тестового фреймворка **Pytest**.

## Покрытие тестами и планы по автоматизации
Файл содержит 210 тест-кейсов. Из них порядка ~200 кейсов (95%) подлежат полной автоматизации с помощью Selenium + Python. Оставшиеся сценарии (например, визуальная оценка дизайна, адаптивности под редкие разрешения, юзабилити-тестирование и субъективные проверки контента) экономически нецелесообразны для автоматизации и остаются в области ручного тестирования (Manual QA).

В рамках текущего этапа проекта из-за ограниченных временных рамок было детально реализовано и запущено **20 автоматизированных тестов** (FOOT, FAU, REC, REG). Все остальные запланированные тест-кейсы будут последовательно добавляться в тестовый фреймворк по аналогии — на базе уже созданной архитектуры Page Object Model (POM) и готовых базовых методов взаимодействия с элементами.

## Архитектура и стек технологий
- **Язык программирования:** *Python*: выбран за лаконичный синтаксис, высокую скорость разработки автотестов и обширную экосистему библиотек для QA
- **Тестовый фреймворк:** *Pytest*: выбран за мощный механизм фикстур и встроенную параметризацию тестов
- **Инструмент автоматизации UI:** *Selenium WebDriver (управление браузером Google Chrome)* - это классический, надежный инструмент для управления браузером Chrome
- **Паттерн проектирования:** *Page Object Model (POM)*: изолирует логику тестов от изменений в UI, сокращая затраты на поддержку кода
- **Стандарт кодирования:** *PEP8*: гарантирует единообразие, читаемость и легкую поддержку кодовой базы

## Объект тестирования (Что проверялось)
- Корректность интерфейса
- Пользовательские сценарии
- Валидация полей
- Динамические элементы
- Интеграционные UI-стыки

## Реализованная техническая часть (Что именно сделано)
- *Базовый класс Page* - создана общая логика ожидания элементов (Explicit Waits) и инициализации драйвера
- *Дерево классов страниц* - реализованы конкретные классы для каждой страницы с изоляцией локаторов
- *Конфигурация Pytest* - написаны фикстуры в conftest.py для безопасного запуска и закрытия сессий Chrome
- *Тестовые наборы:* - разработаны атомарные UI-тесты, проверяющие позитивные и негативные сценарии

## Ограничения проекта и зоны развития
- **Интеграция с API (Postman/Swagger**. При наличии открытой спецификации Swagger было бы целесообразно использовать Postman или библиотеку requests для проведения API-тестирования. Это позволило бы изолированно проверять бизнес-логику бэкенда, проводить быструю подготовку тестовых данных через API и сократить общее время выполнения UI-тестов.
- **Кроссбраузерное тестирование**. Из-за жестких ограничений по срокам проверке подвергся только браузер Google Chrome. В следующих итерациях необходимо настроить запуск тестов в Mozilla Firefox и Safari для минимизации рисков верстки.
- **Мобильное тестирование**. Проверка адаптивности интерфейса на реальных мобильных устройствах или эмуляторах не проводилась из-за дефицита времени. Данная задача вынесена в бэклог для будущих этапов стабилизации продукта.

## Структура проекта

**Diploma/**
- *pages/*                     # Каталог классов веб-страниц (Page Objects)
- - base_page.py           # Базовый класс с общими методами
- - reg_page.py            # Локаторы и методы для формы регистрации (блок REG)
- - auth_page.py           # Локаторы и методы для формы авторизации (блок AUTH)
- *tests/*                     # Каталог с тест-кейсами и проверками (assert)
- - conftest.py            # Pytest-фикстуры (автоматический запуск и закрытие браузера Chrome)
- - test_footer.py         # Автотесты для подвала сайта 
- - test_registration.py   # Автотесты для валидации формы регистрации (REG)
- - test_authorization.py  # Автотесты для валидации формы входа (AUTH)
- *requirements.txt*           # Список внешних зависимостей проекта (библиотек)
- *README.md*                  # Документация проекта (этот файл)
- *test_data.py*               # Python-файл с существующими данными для авторизации / восстановления пароля / регистрации

## Подготовка окружения

Убедитесь, что у вас установлен Python и виртуальное окружение. Активируйте venv и установите все необходимые зависимости из файла `requirements.txt` одной командой. Добавьте данные в test_data.py для авторизации / восстановления пароля / регистрации
